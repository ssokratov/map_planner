# Перевод компендиума Lancer на русский (ru.json)

## Что переводим

Весь текст базы трекера (встроена в `index.html` между `// __DB_START__` и
`// __DB_END__`, ~38 000 английских слов):

| Раздел | Позиций | Что переводить |
|---|---|---|
| weapons | 85 | n (имя), t (тип), d (урон), r (дальность), x (описание) |
| systems | 124 | n (имя), t (тип), x (описание) |
| talents | 29 | n (имя), t (краткое описание), r (имена 3 рангов), d (описания 3 рангов) |
| tags | 67 | n (имя с `{VAL}`), d (описание с `{VAL}`) |
| frames | 29 | n (имя), c (имя Core System), cd (описание Core System), t (трейты) |

Не переводить: `g` у оружия (строка тегов — она соберётся из переведённых
тегов при сборке), статы фреймов (числа), коды маунтов (Aux/Main/Heavy/...),
лицензии и уровни (LL0–LL3 — коды).

## Источник строк

Извлекать строки ТОЛЬКО из встроенной базы в `index.html` (блок
`// __DB_START__ ... // __DB_END__`, распарсить как JSON). Это ровно то,
что показывается на странице. Сырые файлы lancer-data (`/tmp/db/`) могут
отсутствовать — при необходимости скачать заново с
`https://raw.githubusercontent.com/massif-press/lancer-data/master/lib/`.
Не переводить по памяти: каждое русское поле должно соответствовать
конкретной английской строке из базы.

## Формат результата

Итоговый файл — `ru.json` рядом с `index.html`:

```json
{
  "weapons": { "<англ. имя>": {"n": "...", "t": "...", "d": "...", "r": "...", "x": "..."} },
  "systems": { "<англ. имя>": {"n": "...", "t": "...", "x": "..."} },
  "talents": { "<англ. имя>": {"n": "...", "t": "...", "r": ["...", "...", "..."], "d": ["...", "...", "..."]} },
  "tags": { "<id тега>": {"n": "...", "d": "..."} },
  "frames": { "<англ. имя>": {"n": "...", "c": "...", "cd": "...", "t": "..."} }
}
```

Ключи — английские имена (для tags — id вида `tg_reliable`). В полях `x`/`d`/`cd`
сохранять структуру оригинала: абзацы разделять `\n\n`, пункты списков —
`• ` в начале строки (как в базе). Плейсхолдер `{VAL}` в именах и описаниях
тегов сохранять как есть, на том же месте.

## Глоссарий (обязательно, единообразно во всех разделах)

Термины из интерфейса трекера (уже русские): Structure — структура,
Heat — тепло, Stress — стресс, Repairs — ремонты, Overcharge — оверчардж,
Core Power — Core Power (не переводить), SP — SP (не переводить),
HASE — HASE (не переводить).

Типы урона: Kinetic — кинетический, Energy — энергетический,
Explosive — взрывной, Burn — ожог, Heat — тепло.
Дальность: Range — дальность, Threat — угроза, Blast — взрыв, Burst — вспышка,
Line — линия, Cone — конус.
Общие: Accuracy — точность, Difficulty — сложность, Save — спасбросок,
Check — проверка, Attack — атака, Damage — урон, Armor — броня,
Evasion — уклонение, E-Defense — э-защита, Speed — скорость,
Sensors — сенсоры, Tech Attack — техатака, Scene — сцена,
Mission — миссия, Turn — ход, Round — раунд, Action — действие,
Quick Action — быстрое действие, Full Action — полное действие,
Reaction — реакция, Protocol — протокол, Free Action — свободное действие,
Movement — движение, Boost — ускорение, Deployable — развёртываемое,
Drone — дрон, Shield — щит, AI — ИИ.

**Термины-транслитерации (решение Сергея, 2026-11-12): частые действия
игры — не переводить, а транслитерировать как термины, склонять как
существительные мужского рода. Skirmish — Скирмиш** (было расхождение:
«стычка» в 10 местах и «перестрелка» в 1 — унифицировано в Скирмиш;
проверено по EN-оригиналу: каждое Skirmish в тексте — Скирмиш).
Skirmisher как имя трейта фрейма Nelson — **Скирмишер** (2 места: Core
System и трейт); имя таланта Skirmisher — **Застрельщик** (не менять,
это имя собственное таланта). Аудит 2026-11-12: остальные частые действия
единообразны (Boost — ускорение, Barrage — залп, Ram — таран,
Grapple — захват, Lock On — захват цели, Overwatch — наблюдение,
Brace — укрытие, Invade — вторжение, Scan — скан/сканирование,
Bolster — поддержка, Disengage — отход, Stabilize — стабилизация,
Activate — активация, Reload — перезарядка) — их НЕ транслитерировать
без отдельного решения Сергея. Известные систематические омонимии
(«захват» — Grapple и часть Lock On; «укрытие» — Brace и cover) —
оставлены как есть, контекст различает.

Не переводить (имена собственные): GMS, IPS-N, HORUS, Smith-Shimano,
Harrison Armory, COMP/CON, NHP, Lancer, Massif Press, названия лицензий
(они же имена фреймов — переводятся как имена фреймов, см. ниже).

Имена фреймов, оружия, систем, талантов — переводить осмысленно
(Blackbeard — Чёрная Борода, Assault Rifle — штурмовая винтовка,
Crack Shot — меткий стрелок), а не транслитерировать. Имена тегов —
прилагательными/существительными по смыслу (Reliable — надёжное,
Accurate — точное, Seeking — самонаводящееся, Smart — умное,
Arcing — дуговое, AP — бронебойное). Если для имени нет хорошего
перевода — оставить английское и отметить в отчёте.

Стиль: игровой русский, как в интерфейсе трекера; термины — строго
по глоссарию; не выдумывать правила, не сокращать смысл.

## Организация работы (координатор)

- Разбить работу на 5 секций (weapons, systems, talents, tags, frames).
  Системы — самая большая (124 позиции, ~17 000 слов), её дробить на 2–3
  части по алфавиту.
- Каждую секцию (или часть) переводит отдельный подагент; каждый пишет
  СВОЙ файл `ru_<секция>.json` (или `ru_systems_a.json` и т.п.), чтобы
  не было гонок за один файл.
- После всех секций координатор сливает части в один `ru.json` и проверяет
  покрытие: количество ключей в каждой секции == количеству позиций в базе
  (85/124/29/67/29), у каждого ключа — все обязательные поля, ни одного
  пустого перевода, `{VAL}` на месте там, где он есть в оригинале.
- Итог: `ru.json` + короткий отчёт о покрытии и о спорных местах
  (имена без хорошего перевода, неоднозначные термины).
- НЕ трогать `index.html`, `build_db.py`, `smoke_test.js` — их правит
  основной агент после приёмки перевода. Перевод — только JSON-файлы.
