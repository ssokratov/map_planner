# Map Builder — прототип билдера карт для DnD (Godot 4.7.2, GDScript)

Идея: сначала быстро накидать точный, пусть и уродливый, план карты на сетке,
а потом отправить этот план в AI-генерацию с указанием стиля — вместо того чтобы
объяснять словами, какая карта нужна. Репозитория пока нет, проект живёт здесь.

## Запуск

Открыть `project/` в редакторе Godot 4.7.2 и нажать F5, или из терминала:

```
Godot --path project
```

## Управление (приоритет — минимум кликов)

- **Рисование:** зажал левую кнопку и ведёшь — красится вся линия клеток.
  Один инструмент на клетку дважды не ставится (повторное ведение ничего не дублирует).
- **Ластик:** правая кнопка с ведением — снимает верхний объект с клетки.
  Shift + правая кнопка — очистить клетку целиком (объекты + подпись).
- **Мышь:** колесо — зум к курсору, средняя кнопка с ведением — сдвиг карты.
- **Клавиши:** 1 — стена, 2 — дверь, 3 — окно, 4 — яма, 5 — свой тайл,
  6 — текст, 7 — ластик, 8 — границы, 9 — копия, G — переключить сетку,
  F — вписать карту в экран, Ctrl+Z — отмена (до 100 штрихов),
  Delete/Backspace — снять верхний объект клетки под курсором
  (Shift+Delete — всю клетку).
- **Текст:** инструмент «Текст» — клик по клетке, подпись поверх объектов.
  «Свой тайл» — один клик: ставится плейсхолдер «?» и сразу открывается
  поле, что он значит. Ведение с этим инструментом попапов не открывает.

## Что есть в прототипе

- Два типа сетки: квадратная и хексовая (pointy-top, axial-координаты).
  Переключение сетки сохраняет клетки — координаты просто перечитываются
  в новой сетке (квадрат (x, y) → хекс (q, r)).
- Несколько объектов в одной клетке (стек: стена + дверь, яма + подпись и т.д.).
  Состав клетки под курсором показывается в строке статуса внизу.
- Подписи поверх объектов с подложкой для читаемости.
- Автосохранение после каждого штриха в `user://map.json`
  (при следующем запуске карта восстанавливается сама).
- **Экспорт:** кнопка «Экспорт PNG» сохраняет план без интерфейса в
  `user://map_plan.png`. Границы кадра задаёшь ты сам: инструмент
  «Границы» (8) — протащить прямоугольник по холсту (он рисуется
  пунктиром), «Границы по содержимому» — обвести нарисованное с полями,
  «Сбросить границы» — вернуться к авто-кадру. Смысл ручных границ:
  можно оставить пустое место — например, справа или снизу, — куда
  потом добавить легенду. В кадр попадает ровно прямоугольник границ
  (без пунктира и подсветки), сетка, объекты и подписи — как есть.
- **Буфер обмена:** кнопка «Копировать в буфер» рендерит тот же кадр
  и кладёт картинку в системный буфер — сразу Ctrl+V в Gemini или Muse.
  В Godot нет API картинок в буфере, поэтому копирование идёт через
  системный инструмент: Linux — `xclip` (или `wl-copy` на Wayland),
  Windows — PowerShell, macOS — osascript. Если инструмент не найден,
  кнопка честно пишет об этом, а PNG всё равно сохраняется как
  `user://map_clipboard.png` — его можно вставить файлом.
- **Копия:** инструмент «Копия» (9). Alt+клик по клетке — взять её
  содержимое в буфер (все объекты клетки, включая значение своего
  тайла; подпись не копируется). Клик или ведение — поставить буфер
  на клетки: недостающие объекты добавляются, существующие не
  трогаются (у своего тайла обновляется значение). Состав буфера
  виден в строке статуса. Отмена штриха (Ctrl+Z) работает и здесь.
- **Удаление:** Delete или Backspace — снять верхний объект с клетки
  под курсором, Shift+Delete — очистить клетку целиком (объекты +
  подпись). Ластик (7) ведением снимает верхний объект (Shift — всю
  клетку); правая кнопка — так же: снимает верхний объект,
  Shift + правая — всю клетку.

## Веб-экспорт и GitHub Pages

Проект изначально пишется так, чтобы его можно было тестировать в браузере:
всё клиентское (нет сервера, логина и нативных диалогов), весь интерфейс —
внутриигровой, кнопки подписаны, а строка статуса отражает состояние
(инструмент, клетка, содержимое, границы, буфер копии) — по скриншоту видно,
сработал ли клик. Однопоточный web-экспорт (по умолчанию с Godot 4.3)
не требует COOP/COEP-заголовков, которых у GitHub Pages нет.

Локальная сборка (шаблоны экспорта уже есть в системе):

```
mkdir -p build/web
Godot --headless --path project --export-release "Web" build/web/index.html
```

Деплой — как у tn2019quest:

1. Создать **публичный** репозиторий (на бесплатном GitHub Pages
   публикуются только публичные репозитории).
2. Залить код. Коннектор GitHub код пушит, но workflow-файлы — нет
   (403, проверено на tn-проекте), поэтому готовый
   `.github/workflows/deploy.yml` добавляется вручную: через
   веб-интерфейс GitHub или локальный git.
3. Settings → Pages → Source: GitHub Actions.
4. Открыть `https://<user>.github.io/<repo>/`.

Демо для быстрой проверки: `?demo=1` — загружает образец карты
(комната с дверью и окном, яма с подписью, свой тайл, границы
с местом под легенду). Демо-режим не пишет автосейв, поэтому
открыть его — безопасно для настоящей карты. `?grid=hex` — демо
на хексовой сетке.

Веб-отличия от десктопа: «Экспорт PNG» скачивает файл (папка
`user://` в вебе невидима); «Копировать в буфер» идёт через
Clipboard API — на Pages есть и HTTPS, и жест клика, а если браузер
откажет, PNG скачивается как запасной путь. Правая кнопка-ластик
в вебе работает: canvas подавляет контекстное меню.

## Заведомо не сделано (следующие шаги)

- Двери/окна на гранях между клетками — сейчас всё строго по клеткам.
- Заливка областей, прямоугольники, линии стен одним движением.
- Выбор и перетаскивание готовых кусков, слои.
- Авто-легенда в экспорте (используемые тайлы + значения своих тайлов) —
  пока место под легенду задаётся ручными границами, а сама легенда
  добавляется снаружи.
- Хекс-сетка на очень маленьком зуме может тормозить (много линий) —
  лечится отрисовкой сетки в текстуру, если понадобится.
- Визуальная проверка в редакторе ещё не проводилась — headless-тест
  покрывает только логику (сетки, стеки, JSON, границы, загрузку
  скриптов и сцены).
